# 0005 — Редактирование в памяти и границы Unicode

Статус: принято для прототипа 0.3.0, 1 ноября 2026 года.

## Решение

Операции редактирования, выделение и линейная Undo/Redo реализованы самостоятельно в `paperik-document::editor`. Win32 отвечает за системный курсор, ввод, IME и буфер обмена. Попадание мыши и подсветка используют HitTest API тех же DirectWrite layouts, которые рисуются. Автоматические метки списков не входят в редактируемый текст.

Для границ символов и слов подключена только базовая `unicode-segmentation = 1.13.3`, Unicode 17/UAX #29. Самостоятельная таблица всех графем Unicode излишне увеличила бы объём и риск ошибок. У библиотеки нет runtime-зависимостей и C/C++ build step; GNU/LLVM-сборка сохраняется. Лицензия MIT OR Apache-2.0, выбран MIT; COPYRIGHT и точные тексты включены. Источник: https://docs.rs/crate/unicode-segmentation/1.13.3.

Позиции UTF-16 согласованы с DirectWrite, редактирование выполняется на границах графем. Сначала строятся новая модель и вёрстка; после успеха они фиксируются вместе. При ошибке прежние модель и история остаются действующими. Подготовленная операция связана с поколением модели/выделения.

## Последствия и проверка

Сохранение DOCX намеренно остаётся PPK-009: новая модель пока живёт в памяти, неизменяемый пакет не сериализуется. Интерфейс и предупреждение при закрытии явно сообщают об этом. Undo/Redo ограничена по числу снимков и оценке памяти; постоянное дерево версий не заявляется.

Проверяются сохранность runs/стилей, Unicode, разрывы и вставка, нумерация, отмена, геометрия курсора, переносы, пагинация и callback собственного скрытого окна. Точность исходного шаблона повторно сверена с независимым PDF. Интерактивный ввод и реальная IME требуют отдельного прогона, см. `../testing.md`.
