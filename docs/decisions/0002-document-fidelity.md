# 0002 Сохранение оформления и собственный движок DOCX

Дата: 1 ноября 2026 года. Статус: принято; техническая реализация и точность ещё не проверены.

## Контекст

Главный сценарий — заменить чужие данные и текст в готовом документе, сохранив оформление. Пользователь требует самостоятельной работы и разрешает увеличение количества страниц. В первом образце часть свойств наследуется из стилей, а отдельные области имеют отличающееся оформление.

## Решение

Разрабатывать собственные модель документа, разрешение свойств, расчёт страниц и операции редактирования. Использовать исходный DOCX как основу сохранения. Неизменённые данные сохранять, а изменённые области проверять отдельно. Не преобразовывать весь документ в упрощённый формат с последующей пересборкой как универсальную стратегию точности.

Сохранять фактические размеры шрифтов, интервалы, отступы, поля и другие свойства, включая исключения. Дополнительные страницы при росте текста допустимы. Автоматическое уменьшение оформления ради прежнего числа страниц запрещено.

Хранить исходник и историю, применять изменения транзакционно. Не поддерживаемую безопасно операцию отклонять без изменения исходника. ИИ формирует проверяемые команды и не заменяет механизм сохранения оформления.

## Последствия

Поддержка развивается по проверяемым подмножествам DOCX. Цель полной совместимости остаётся в требованиях; достижение не предполагается из факта чтения XML. Сохранность пакета, отображение и редактирование тестируются раздельно.

Полная пиксельная проверка требует независимого эталона и одинаковых условий отображения. Без него структурные тесты доказывают только проверенные свойства. Скан или фотография не содержит полной исходной структуры DOCX; восстановление оформления через OCR имеет отдельные границы точности.
