# 0003 Сборка без Microsoft Build Tools

Дата: 1 ноября 2026 года. Статус: принято пользователем, проверено локально.

## Контекст

Пользователь запросил проверку лицензий до разработки. Условия установленного Microsoft Build Tools требуют отдельного основания для обычного использования; наличие лицензии Visual Studio не подтверждено. Пользователь выбрал вариант без Microsoft Build Tools.

## Решение

Использовать host и target `1.98.1-x86_64-pc-windows-gnullvm`, компонент `rust-mingw`, встроенный `rust-lld` и статическое включение runtime. Не вызывать MSVC и `link.exe`. Использовать `windows-sys 0.61.2` с минимально необходимыми функциями и сохранить MIT-уведомления для него и `windows-link 0.2.1`.

Первая сборка без статической настройки успешно запускалась через Cargo, но автономный запуск выявил зависимость от `libunwind.dll` из среды компилятора. После включения `target-feature=+crt-static` копия release-exe успешно прошла проверку с очищенным PATH в отдельном каталоге. Это обнаруженное и устранённое ограничение первой конфигурации, а не основание скрывать runtime-зависимости.

## Последствия

Требуется отдельный GNU/LLVM-host toolchain, основной Rust пользователя не меняется. GNU/LLVM-цель Tier 2 нуждается в собственной проверке. К приложению прилагаются уведомления Rust, MinGW-w64 и LLVM runtime. Использование Windows API сохраняется; системные DLL и шрифты не поставляются.

Чистая Windows VM ещё не проверена. При появлении зависимостей с C/C++-кодом нужна новая оценка инструментов и лицензий. Выбор лицензии собственного кода остаётся за владельцем проекта.
