# Условия реализации и распространения Paperik

Проверено по перечисленным первичным источникам 1 ноября 2026 года. Это рабочая проверка выбранной реализации, а не гарантия отсутствия любых прав третьих лиц во всех странах. Правила переоцениваются при добавлении компонентов и подготовке публичной поставки.

## Чтение и запись DOCX

Собственная реализация формата допустима в рамках условий спецификаций. [ECMA-376](https://ecma-international.org/publications-and-standards/standards/ecma-376/) опубликован как стандарт Office Open XML. В [Open Specification Promise Microsoft](https://learn.microsoft.com/en-us/openspecs/dev_center/ms-devcentlp/1c24c7c8-28b0-4ce1-a47d-95fe1ff504bc) перечислены ECMA-376, ISO/IEC 29500:2008/2012/2016 и соответствующие implementation notes.

OSP касается необходимых патентных требований Microsoft для покрытой реализации с оговорёнными условиями, а не всех технологий или прав третьих лиц. Для конкретного расширения надо проверить его спецификацию и покрытие отдельно. [FAQ Microsoft](https://learn.microsoft.com/en-us/openspecs/dev_center/ms-devcentlp/03347966-f8ff-4d53-a05e-63419d4132e2) допускает частичную реализацию и не требует подписывать соглашение или связываться с Microsoft для получения преимущества OSP. Отдельная покупка Word для самостоятельной реализации покрытого формата из этих условий не следует.

Разрешение реализовывать формат не даёт прав копировать реализацию редактора, распространять чужие документы, обходить защиту или использовать чужие товарные знаки как свои. Paperik реализует формат самостоятельно и не запускает сторонние офисные движки.

## Среда сборки и Windows

[Условия Microsoft Build Tools 2026](https://visualstudio.microsoft.com/license-terms/vs2026-ga-diagnostic-buildtools/) связывают обычное использование с действующей лицензией Visual Studio и отдельно описывают исключение для определённых сторонних открытых C++-зависимостей. Наличие установленного Build Tools не доказывает наличие нужного права использования. Пользователь не подтвердил такую лицензию, поэтому сборка Paperik не должна вызывать MSVC, `link.exe` и инструменты из Build Tools.

Выбрана отдельная среда Rust `x86_64-pc-windows-gnullvm` с `rust-mingw` и линкером `rust-lld`, без Microsoft Build Tools. Этот способ для чистого Rust описан в [официальной документации Rust](https://doc.rust-lang.org/rustc/platform-support/windows-gnullvm.html). Windows API вызываются через открытые привязки; Windows остаётся системным требованием. Системные DLL и шрифты не копируются в поставку. Будущие зависимости с C/C++-кодом потребуют повторной проверки среды сборки.

## Rust и зависимости

[Rust](https://github.com/rust-lang/rust/blob/main/COPYRIGHT) преимущественно лицензирован как MIT OR Apache-2.0, с отдельными уведомлениями для включённых компонентов. Это не обязывает автоматически открывать исходники Paperik. Фактический комплект стандартной библиотеки и runtime проверяется по уведомлениям выбранного toolchain.

Первая внешняя зависимость — `windows-sys 0.61.2` и её транзитивная зависимость `windows-link 0.2.1`, обе MIT OR Apache-2.0. Выбран вариант MIT; его текст и copyright сохраняются в `licenses/`. Назначение — вызов Windows API, это не готовый движок документов. Перед распространением включаются уведомления всех реально включённых компонентов, а не только прямых Cargo-зависимостей. Отсутствие строки соавторства в коммите не отменяет лицензионные уведомления зависимостей.

## Шрифты

[FAQ Microsoft о шрифтах](https://learn.microsoft.com/en-us/typography/fonts/font-faq) допускает использование системных шрифтов приложениями для отображения и редактирования, но не даёт общего права распространять сами файлы шрифтов. Paperik использует установленные шрифты и не кладёт Times New Roman, Aptos или Segoe UI в архив с приложением. Встраивание шрифтов в документы/PDF и перенос на сервер проверяются по разрешениям конкретного шрифта.

## Ollama, модели и собственный код

[Исходный проект Ollama](https://github.com/ollama/ollama/blob/main/LICENSE) имеет MIT-лицензию; веса моделей имеют собственные условия. Пока приложение не поставляет Ollama или веса. Для будущего включения OCR, генераторов изображений или моделей проверяются их конкретные версии и права.

Лицензия собственных исходников Paperik пока не выбрана. В Cargo установлено `publish = false`, открытая лицензия проекту автоматически не назначается. Публичный репозиторий сам по себе не заменяет лицензию; у GitHub есть отдельные условия просмотра и форка. См. [руководство GitHub](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/licensing-a-repository). Решение о дальнейших правах использования кода принимает владелец проекта.

## Перед публичным выпуском

- Сверить Cargo.lock и состав бинарного файла с уведомлениями Rust/runtime и библиотек.
- Включить тексты лицензий и copyright фактически распространяемых компонентов.
- Не включать системные DLL, файлы шрифтов, личные документы или веса без отдельно проверенных прав.
- Уточнить лицензию собственных исходников, условия поставки и разрешения конкретных моделей.
- Повторить проверку, если изменены toolchain, зависимости, формат экспорта или способ распространения.
