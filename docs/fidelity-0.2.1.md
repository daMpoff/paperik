# Точность первого шаблона: 0.2.1

Дата: 1 ноября 2026 года. Эталон — предоставленный пользователем PDF, созданный Microsoft Word 2024. DOCX и PDF прочитаны локально и не изменены. Личные файлы, текст, изображения страниц и локальные пути не публикуются.

## Почему было 10 страниц

В 0.2.0 получалось 272 строки основного документа вместо 263. Округление ширин в GDI-совместимой вёрстке при 96 dpi давало лишние переносы. Затем пять почти заполненных абзацев списка не помещались из-за отсутствия сжатия пробелов при выравнивании по ширине. Эти дополнительные строки вытесняли конец на десятую страницу. Ширины теперь измеряются в физических единицах DirectWrite, без привязки к DPI экрана.

Наш алгоритм для современного режима совместимости Word 2013+ выбирает допустимый перенос с меньшей относительной корректировкой пробелов; допускается сжатие обычных межсловных пробелов до 75% естественного продвижения. NBSP, табуляции, размеры и контуры букв не сжимаются. Политика проверена на данном сценарии; универсальное воспроизведение всех правил Word не заявляется. Для старых режимов сжатие без соответствующего флага совместимости не включается.

Дополнительно исправлены widowControl для абзацев из двух строк, перенос выражений со знаком `/`, положение базовой линии при кратном интервале и явное применение настроек OpenType. В шаблоне лигатуры выключены; `kern=0` используется как выключенный кернинг в поведении Word. Это важно для ширин заголовков. Высота строк округляется до twip; дополнительный кратный интервал остаётся после базовой линии. Горизонтальное отсечение курсивных выносов по границе текстовой колонки убрано.

Правила основаны на собственной реализации и проверке эталона. Документация API: [метрики шрифта](https://learn.microsoft.com/en-us/windows/win32/api/dwrite/ns-dwrite-dwrite_font_metrics), [интервал OOXML](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.wordprocessing.spacingbetweenlines.line), [коррекция продвижения символа](https://learn.microsoft.com/en-us/windows/win32/api/dwrite_1/nf-dwrite_1-idwritetextlayout1-setcharacterspacing). Исходники и движки сторонних редакторов не использовались.

## Что совпало

- 9 страниц; все восемь переходов между ними совпали с PDF и кэшированными отметками DOCX. Отметки не участвуют в расчёте страниц.
- 237 непустых строк: совпали и состав строк, и принадлежность страницам.
- 8186 непробельных символов: нет пропущенных, добавленных или перенесённых на другую страницу.
- Геометрия A4, поля 30/15/20/20 мм, исходные шрифты 14/16 пт, интервалы и отступы сохранены.
- Положение символов по X: медиана ошибки 0,090 пт, p95 0,225 пт, максимум 0,454 пт (около 0,160 мм).
- Базовые линии: медиана ошибки 0,030 пт, максимум 0,140 пт (около 0,049 мм).

Система проверки: Windows x64 26300.9711; Rust 1.98.1 GNU/LLVM; установленный Times New Roman 7.12. Проверка геометрии 96/192 dpi выполняется на собственной фикстуре. Она не заменяет проверку перетаскивания окна между реальными мониторами.

## Как повторить

Собрать release и вызвать `paperik.exe --render-pages "образец.docx" "новая-папка"`. Собственный расчёт страниц и путь отрисовки совпадают с экранным; PNG кодируется системным Windows Imaging Component, 144 dpi. В каталоге появляются PNG, `layout.tsv` и `glyphs.tsv`. TSV содержит индексы UTF-16 и координаты без текста. Экспорт не читает PDF и не зависит от эталона.

Для локального сравнения используется наша утилита `tools/qa/compare_docx_pdf.py`:

```powershell
python tools/qa/compare_docx_pdf.py --docx "образец.docx" --pdf "эталон.pdf" --render-dir "новая-папка" --output "comparison.json"
```

Нужны Python и `pdfplumber==0.11.9` только для этой необязательной QA-утилиты. Они не включены в exe и не участвуют в чтении или отображении DOCX приложением. Из PDF извлекаются координаты символов; текст сопоставляется с XML и UTF-16-позициями нашего рендера. Для первого шаблона приняты пределы 0,5 пт по X и 0,2 пт по базовой линии. Выходной JSON содержит только агрегаты. Сводка проверенного результата: `qa/reference-template-0.2.1.json`.

PNG эталона независимо получены Poppler при 144 dpi. Все девять пар страниц осмотрены, отдельно проверены титул и основные списки. Измерение координат дополняет визуальный осмотр, а не заменяет его.

## Границы результата

Это проверка конкретного текстового шаблона и его PDF. Отличия сглаживания DirectWrite и PDF остаются; пиксельная идентичность не заявляется. Таблицы, изображения, формулы, сложные языки/типографика, несколько разделов и прочие неподдерживаемые случаи не покрыты. Редактирование и сохранение DOCX ещё не реализованы. ИИ не участвует в расчёте страниц.
