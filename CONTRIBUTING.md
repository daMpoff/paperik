# Работа над Paperik

## Перед началом задачи

1. Прочитать `AGENTS.md` и документы, связанные с задачей.
2. Выбрать пункт из `BACKLOG.md`, проверить зависимости и определить ожидаемый результат.
3. Внести минимальное законченное изменение. Обновить связанные документы и критерии приёмки при согласованном изменении требований.
4. Выполнить применимые проверки из `docs/testing.md` и указать их результаты. Невыполненные проверки описать честно.
5. Отметить задачу завершённой только при выполнении критериев приёмки.

В репозитории есть Cargo workspace и собственный редактор DOCX с сохранением копии и восстановлением сессии. Перед коммитом исходного кода выполнять `pwsh -NoProfile -File scripts/build.ps1 -Configuration Release -Check -Package`. Команда проверяет форматирование, Clippy, интеграционные тесты, release-сборку и запуск поставки с очищенным PATH. Debug-сборка проверяется отдельно с `-Configuration Debug`. См. `docs/build.md`. Для изменений документации проверять ссылки и согласованность требований; повторная сборка нужна, если изменены инструкции сборки или исполняемые примеры.

## Стиль сообщений коммитов

Используется Conventional Commits с русскими описанием и телом. Заголовок отвечает на вопрос «что сделано».

```text
тип(область): описание

Причина и существенные детали, если они нужны.
```

Область необязательна. Тип и область пишутся строчными английскими метками. Заголовок — без точки в конце и без эмодзи; желательно до 72 символов.

- `feat` — новая возможность.
- `fix` — исправление ошибки.
- `perf` — улучшение производительности, подтверждённое измерениями.
- `refactor` — изменение внутреннего устройства без изменения поведения.
- `test` — тесты и тестовые данные.
- `docs` — документация.
- `build` — сборка, упаковка и зависимости.
- `ci` — автоматические проверки.
- `chore` — обслуживание проекта.
- `style` — форматирование кода без изменения поведения; не изменение внешнего вида приложения.
- `revert` — отмена изменения.

Области по необходимости: `ui`, `docx`, `layout`, `render`, `ai`, `history`, `windows`.

```text
feat(ui): добавлена панель файлов
feat(docx): добавлено открытие документов
feat(ai): добавлено определение заменяемых полей шаблона
fix(layout): исправлен отступ первой строки
perf(render): ускорена отрисовка страниц
refactor(history): версии отделены от операций документа
test(docx): добавлены проверки наследования стилей
docs: обновлено описание архитектуры
build(windows): настроена сборка exe
ci: добавлены проверки для запросов на слияние
```

Пример с пояснением:

```text
fix(docx): сохранено оформление при замене ФИО

ФИО может быть разбито на несколько фрагментов с разным оформлением.
При замене сохранены свойства незатронутых фрагментов.
```

Нарушение обратной совместимости обозначается `!` перед двоеточием. При необходимости после пустой строки добавляется `BREAKING CHANGE:` с пояснением на русском. Номера задач указываются только для существующих задач; локальные идентификаторы backlog имеют вид `PPK-001`.

Один коммит содержит одно законченное логическое изменение. Заголовки вроде «правки», «обновления» и «исправления» без уточнений не используются.

Строка `Co-authored-by` и другие строки атрибуции соавторства не добавляются. Для авторства используются настройки Git пользователя; вымышленные данные автора не подставляются.

## Зависимости и данные

Для каждой дополнительной зависимости указываются назначение, лицензия, необходимость и влияние на поставку. Включение готового движка документов запрещено независимо от лицензии.

Личные исходники хранятся в игнорируемом каталоге `local/`. Публикуемые фикстуры создаются самостоятельно и не содержат чужих ФИО, групп, подписей, метаданных и текста работ. Проверка `.gitignore` не заменяет просмотр состава коммита.

## Ветви и слияние

Основная ветвь — `main`. После первого коммита изменения можно вести в коротких тематических ветвях, например `feat/docx-import` или `fix/paragraph-spacing`. Переписывание опубликованной истории и принудительная отправка не являются обычным рабочим процессом.

Источник формата сообщений: [Conventional Commits 1.0.0](https://www.conventionalcommits.org/ru/v1.0.0/). Русский язык, форма «что сделано», ограничение длины и запрет соавторства — правила Paperik.
