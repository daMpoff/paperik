# 0013 — Структурные правки таблиц

Решение принято для локальной сборки после 0.5.0. Оно расширяет [0012](0012-block-text-editing.md).

## Контекст

Вставка и удаление ячеек меняют их адреса в основном XML. Для сохранения оформления нужны исходные свойства таблицы, строки и ячейки. История и восстановление должны возвращать сетку вместе с текстом.

## Решение

Редактор сначала переносит ожидающие текстовые правки в основной XML и сверяет результат с моделью. Структурная команда меняет целевую таблицу и повторно импортирует документ. При успехе фоновой вёрстки редактор применяет команду целиком. Правка хранит новую редакцию основного XML поверх общего исходного пакета.

Сетка `tblGrid` задаёт ширины столбцов. `gridSpan` и `vMerge` описывают прямоугольные объединения. Строки, связанные вертикальным объединением, размещаются вместе. [Сетка OOXML](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.wordprocessing.tablegrid), [вертикальное объединение OOXML](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.wordprocessing.verticalmerge).

Экспорт заменяет основной XML и сохраняет незатронутые части ZIP. В снимке восстановления v2 исходный пакет и уникальные редакции XML хранятся по одному экземпляру. Чтение снимков v1 сохраняется.

## Проверка и границы

Проверяются импорт сохранённой копии, сохранность незатронутых данных ZIP, наследование свойств, отказы без частичных изменений, Undo/Redo и восстановление снимка. Интерфейс использует меню Win32 и вёрстку Paperik. Область вертикального объединения должна помещаться на странице. [Управление и ограничения](../complex-documents.md).
