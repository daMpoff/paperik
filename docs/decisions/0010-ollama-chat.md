# 0010 — Локальный чат Ollama в нативной панели

Статус: принято для локальной реализации, без коммита и публикации.

Используем собственный HTTP-клиент на std::net, отдельный worker и нативные Win32 EDIT/COMBOBOX/BUTTON. Готовый редактор, веб-оболочка, SDK провайдера и новые crates не требуются. Первая задача ограничена выбором модели и потоковым диалогом; модель не изменяет документ.

JSON разбирает Windows.Data.Json через существующий windows 0.62.2 с дополнительными features. Фабрики активации принадлежат конкретному MTA и освобождаются перед RoUninitialize; статический кэш активации между перезапусками worker не используется. Системные COM-объекты не пересылаются в UI. Основание API: [RoGetActivationFactory](https://learn.microsoft.com/en-us/windows/win32/api/roapi/nf-roapi-rogetactivationfactory).

Очередь ограничена одной задачей, дельты объединяются и забираются UI каждые 50 мс. Отмена закрывает поток после очередной проверки; Drop не ждёт завершения I/O. Установлены границы HTTP/JSON/контекста и тайм-ауты. Данные документа и его worker от чата независимы.

Разрешён только loopback без прокси/redirect; перед передачей сообщения проверяются remote-метаданные модели. Обновление списка не выбирает модель автоматически. Нативные поля сохраняют обычное выделение, буфер обмена и ввод Windows. Панель следует цветам бренда; прежние сведения о документе доступны переключателем.

Цена решения: клиент поддерживает ограниченное подмножество HTTP и только локальную Ollama. Постоянная история, внешние API и автоматические команды требуют отдельных решений. [Управление и точные пределы](../ollama.md), [проверки](../testing.md).
