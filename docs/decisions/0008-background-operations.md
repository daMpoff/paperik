# 0008 — Фоновые операции и согласованный снимок окна

Статус: принято для ветки main после 0.5.0, 1 ноября 2026 года.

## Решение

Один поток `paperik-document` на окно выполняет открытие, подготовку правки, полную вёрстку, экспорт и поиск восстановления. Он получает собственные данные и возвращает результат через ограниченный канал. У него нет HWND, ссылки на State и ресурсов Direct2D. Отмена помечает активный результат непригодным для установки; следующий запрос запускается после освобождения потока. При закрытии чтение можно отсоединить, поскольку оно не обращается к окну.

Текущий документ и документы линейной истории в Editor хранятся через `Arc<Document>`. Снимок для фоновой операции копирует ограниченные метаданные истории и счётчики ссылок, без глубокого копирования текста. Подготовка изменённой модели, расчёт памяти истории и её экспорт остаются в фоне. Изменение по-прежнему принимается целиком вместе с успешной геометрией. Формат восстановления v1 не меняется.

DirectWrite создаёт шрифты и раскладку в рабочем потоке; привязки закреплённого windows-rs разрешают Send/Sync для этих интерфейсов. До передачи в окно раскладка содержит только диапазоны цветов. Кисти и render target Direct2D создаются/используются в потоке рисования и не пересылаются. Цветовые эффекты назначаются только диапазонам рисуемой строки: обработка большого абзаца не повторяется целиком для каждой видимой строки.

Ввод сериализуется ограниченной очередью. Перемещение курсора/выделение во время задачи приостановлены, чтобы возвращённый снимок не перетёр более новое выделение. Сохранение подтверждает только свой checkpoint stamp; ввод во время записи применяется позже и снова делает документ несохранённым. Ошибка сохраняет прежнюю модель и остаётся видимой.

Контрольные сообщения автосохранения неблокирующие. Хотя транспорт использует стандартный channel, логика допускает не более одного checkpoint, одного ожидающего Clean и финального Stop. Новый checkpoint не ставится до подтверждения Clean. Retire возвращает подтверждение без join в UI; штатное закрытие ждёт его через таймер. Drop окна отсоединяет worker и сохраняет последний черновик без ложного Clean.

## Последствия и проверки

Отмена кооперативная; незавершённый системный вызов нельзя принудительно остановить. Сохранение копии завершается без обрыва, остальные действия ждут его результата. Полная вёрстка и рисование видимых страниц остаются отдельными расходами; холодный кадр и экстремальные документы требуют дальнейшего профилирования.

Проверяются ограничение очереди, отменённый результат, отсутствие join при заблокированном чтении, порядок ввода, сохранённый снимок при новом вводе, отзывчивость скрытого нативного окна и ожидание завершения черновика. Добавлен отдельный release-пробник задержек на синтетическом документе. [Управление](../async-operations.md), [результаты](../testing.md).

Платформенные основания: [домены ресурсов Direct2D](https://learn.microsoft.com/en-us/windows/win32/direct2d/resources-and-resource-domains), [многопоточная работа Direct2D](https://learn.microsoft.com/en-us/windows/win32/direct2d/multi-threaded-direct2d-apps). Готовые движки и новые зависимости не добавлены.
